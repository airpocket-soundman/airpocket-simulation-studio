# Saved Inputs

Repository-version reference. Discover actual connected tools before using names below; older registered servers may expose only a subset. Read only the sections needed for the task.

## Bounded input inspection (prefer over legacy full-study replies)

If the actual server exposes it, use existing `studio_inspect_project({path,section:"study",expectedRevision?,pointer?,offset:0,limit:20})` to read input without a complete nested physical payload. This is an opt-in extension to the existing tool, not a new tool. Browser callers use `studioApi.inspectInput(args)` or inspect-scope `studio_browser_call({sessionId,method:"inspectInput",args})`. Sections are project, study, material, conditions, provenance, selection, source, meshes, meshSettings, units and intent. Default section in the shared/live API is project.

Responses contain schemaVersion:1, revision, section, pointer, exists, units and limitations; an existing value has a descriptor, with a page when applicable. Start at the section root, then follow returned absolute RFC6901 pointers inside that same section, passing the returned revision as expectedRevision. For example, inspect conditions then `/conditions/0`; escape literal `~` as `~0` and `/` as `~1`. Invalid pointers, pointers escaping the selected section and stale revisions are refused. Missing paths/sections return exists:false rather than fabricated defaults.

Offset defaults to 0, limit to 20. Object keys are sorted and paged at most 50; array pages at most 200. Nested objects/arrays and long source strings return hash/count/omission descriptors rather than full payloads. Explicit string pointers return page.text in pages of at most 200 UTF-16 code units, not a byte count. Replies are bounded to 65,536 UTF-8 bytes. Scalars report units only where known; do not infer absent units or sources from a descriptor. Read only the relevant study/material/condition/evidence pages and preserve their revision for edits/previews.

The saved-file tool requires explicit section for this bounded mode and refuses mixing it with legacy geometry/face/full-study options. Without section it retains the old reply shape, which may include huge study/source arrays and is **not bounded**; pointer/offset/limit/expectedRevision are refused without section. On an older registered server lacking the extension, do not claim bounded inspection works: use the local repository fallback below when necessary and report that different implementation. Inspection verifies input identity/structure, not material source truth or complete physical applicability.



Specialize the user's own LLM as a CAE agent; this application does not supply a proprietary AI subscription. Use the local `airpocket-studio` MCP server for saved JSON projects. The checkout normally lives at `D:/github/airpocket-soundman/airpocket-simulation-studio`; reuse its actual location if different.

- `studio_capabilities`: use when choosing/checking an execution path to discover actual Node engine methods, candidate status, units and optional connector/export limits. It is not a prerequisite for input-only reads or previews. Browser capability metadata does not prove a GPU adapter is available.
- `studio_diagnose_execution`: inspect a saved project for unsupported method/study/material combinations before solving. Stable codes and suggestions support repair, but `completePreflight:false` means units, physical inputs, constraints and mesh still need validation. Do not interpret an empty list as a safe or accurate model.
- `studio_progress`: use only for questions about development/publication status or outstanding tasks. It can return the full roadmap; do not call it for ordinary input inspection, parameter preview or result measurement. Released features still have limits; consult applicable physics references when changing models.
- `studio_inspect_project({path,meshIndex?,faceOffset?,faceLimit?})`: validate saved inputs, inspect study/conditions and get compact dimension bounds. Explicit `meshIndex` requests face candidates (default 20, maximum 50) with area/centroid/bounds/normals and SHA-256 `displayMeshRevision`. Select a candidate through batch `selectCadFace(mesh,faceId)`. Face IDs belong to this display-mesh revision, including STEP; STL triangles/remeshed tags are not persistent CAD identities. Do not infer exact surface types. Prefer the user's project; do not silently substitute a demo or invent material properties.
- `studio_edit_project`: atomically edit an existing saved project into a new `outputPath`. Use `revision` from `studio_inspect_project` as `expectedRevision`, with `operations:[{method,args}]` (1–100 commands). Supported selection, condition, material, study, mesh, `setInputProvenance(document)` and `setAnalysisIntent({mode})` methods are listed in `docs/automation.md`; `args` uses each method's positional arguments. Stale revisions or failed commands reject the batch. Inputs and existing outputs remain intact. Required-input/provenance contracts do not cover every physical model.
- `studio_import_project({path,outputPath,scaleToMm?,name?})`: import STEP/STP through OCCT with mm normalization and preserved CAD-face mapping; STL requires explicit positive `scaleToMm` and the supported closed outward convex shell. Input limit: 50 MiB. Save to a new JSON path.
- `studio_create_builtin_project({source,outputPath,name?})`: create explicit mm-based box, boxes, fixed cylinder, sphere or tube geometry without inventing material values or boundaries. Read `docs/automation.md` for source parameters.
- `studio_preflight_project({path,method?,operation?,mode?})`: obtain required pointers and repair diagnostics before execution. `completePreflight:false` preserves the need for post-mesh and physical validation. Execution is gated by the same inspection.
- `studio_analyze`: same CPU Worker as the browser. Supply absolute `path` and a new `outputPath`, mesh `size` in mm and optional CPU `method`. Existing outputs are refused. The response contains metrics; the file contains mesh, input, result and calculation settings. Node execution does not verify browser/GPU behavior.
- `studio_start_analysis`, `studio_job_status`, `studio_job_events`, `studio_cancel_job`, `studio_release_job`: asynchronous CPU jobs with frozen input, bounded observations and optional provisional field artifacts. Use these for monitoring rather than blocking `studio_analyze`. See the workflow below.
- `studio_job_artifact({jobId,artifactId,point?,bodyIndex?,elementIndex?,offset?,limit?})`: inspect a registered intermediate artifact with hash/input/mesh checks. Default to summaries; request point interpolation in mm or pages of up to 200 nodes/values when needed. It does not accept arbitrary paths, and released jobs lose their artifact registration.
- `studio_probe`: measure a saved analysis at `point:[x,y,z]` in mm. Fields carry physical units; outside points are refused. Specify the element to disambiguate multiple bodies. Saved results are validated first.
- `studio_validate_cases`: validate case archives and return comparison metrics.

Case/result validation recomputes assessment mode/provisional status from saved inputs and rejects archives that falsely remove provisional status. Old archives without assessment retain compatibility. CAD updates reset existing evidence entries to unconfirmed, clear assumptions and user confirmation; recheck regions and evidence before solving. The edit batch supports 18 methods; Default MCP exposes 29 tools; connector mode exposes 31.

If MCP tools have not loaded in the current chat, import `callStudioTool` from `scripts/studio-mcp.mjs` using a short Node script or the persistent Node tool. `npm run mcp` starts a protocol server, not an interactive shell. A fresh clone needs `npm ci` and `npm run build` to prepare WASM assets.

- `studio_material_catalog`: search 91 preinstalled polymer references by family/filler/content or retrieve by id. Read `docs/polymer-library.md`; distinguish published tensile modulus from flexural modulus, user-assumed Poisson ratio, missing data and experimental formulations. Do not present the displayed 0.35 as a published measurement.

For iterative work, explain which inputs came from the user or measured sources and which remain assumptions. Confirm missing physical support/load/material information instead of making the model solvable by changing the intended physics. Preserve the input/result version and compare like-for-like cases.

The new `quantitative`/`exploratory` input contract covers static isotropic linear structure, isotropic modal structure (including supported uniform-temperature interpolation), static orthotropic linear structure, static temperature-dependent/thermal-stress isotropic structure, small-strain J2 and compressible Neo-Hookean structure, thermal conduction, acoustic waves and supported channel/exterior Stokes flow; other study/material combinations may return `PREFLIGHT_CONTRACT_LIMITED`. Old projects without intent/evidence stay `legacy`, which waives new evidence registration but never fills missing material properties or certifies quantitative inputs. Missing solver-required Young's modulus, Poisson ratio or other properties still cause `MATERIAL_REQUIRED`. Old inputs with no gravity specification use zero gravity. Use the preflight report's `requiredPointers` rather than guessing which evidence is required. Store each exact value at its JSON Pointer in `project.inputProvenance={schemaVersion:1,entries:[{pointer,value,source:{kind,reference?,revision?},rationale,applicability,assumption:null|string,status:"confirmed"|"unconfirmed"}]}`. Sources distinguish user input, measured documents, CAD and agent proposals. Documents/CAD require a reference and revision; confirmed agent proposals also require `confirmation:{by:"user",note}`. LLM confidence is not physical evidence. Value changes invalidate old evidence. Quantitative runs reject unconfirmed required inputs; exploratory runs require an explicit value and assumption and retain provisional status. Successful preflight is not complete physical validation: mesh quality, transferred regions and constraint rank still need checks after meshing.

For iterative jobs:

1. Check capabilities, execution diagnostics and `studio_preflight_project` for the installed version. Inspect the saved input and missing physical assumptions. For a new quantitative/exploratory run, use `studio_edit_project` to set intent and evidence for every returned `requiredPointer`, then repeat preflight until `allowed:true`. Preserve actual sources and declared assumptions.
2. Start with absolute `path`, new `outputPath`, and a unique `requestId`. Retain `jobId` and `inputRevision`. An identical retry returns the same retained job; changed input/settings/output require a new request ID.
3. Poll `studio_job_events` at a frequency useful for the computation, passing the returned `nextSequence` as `afterSequence`. Drain pages while `hasMore`; `truncated` means observations were dropped. Empty pages do not mean completion: check `studio_job_status`.
4. Review summaries and needed artifacts through `studio_job_artifact`, `studio_job_artifacts`, matching job/input revision. `includeFields:true` writes provisional mesh/time fields under a new `outputPath + ".intermediate"` directory. Field files reference their saved corresponding mesh through `meshArtifact`. The default total is capped at 64 MB; an `observation-limit` event means summaries continue without further field storage.
5. Check terminal status and the final artifact before comparing results. Never treat provisional or unconverged observations as final validated physics. Inspect the next input's revision, use `studio_edit_project` to save intended setting changes to a new path, then start a new run with that path and a new request ID. Do not substitute a job's `inputRevision` for the inspected edit revision: normalization can make them differ. Do not modify a running job or silently change supports, loads, material or other physical intent to obtain convergence. Preserve the user's intended physics and request missing physical information when needed.

Default mode exposes 29 tools; connector mode exposes 31. Saved `output.analysisAssessment` and `result.analysisAssessment` retain input mode, assumptions/provisional status and remaining checks. `job.final:true` means publication completed; `job.provisional` can remain true for assumed inputs. Do not equate a saved final artifact with verified physics. Job metadata/events and request IDs live only in the same MCP/Node process (default 32 jobs, 256 events each); retain that process for direct Node calls. Release jobs only after terminal state and executionSettled:true (resourceState:"settled") to free retention slots; saved files remain, and a released request ID can execute again. Cancellation stops `running` jobs, but final file publication in `saving` cannot be cancelled. Computation times out after 120 seconds by default; restart recovery is unsupported. Intermediate observations depend on the solver and do not cover every iteration or field. Browser jobs provide summaries by default; includeFields:true retains bounded in-memory artifacts through the connector. See `docs/automation.md` for contracts and limits.

## Apply catalog references

After `studio_material_catalog`, apply references through `studio_edit_project` or live `edit` with `{method:"applyCatalogMaterial",args:[{id,expectedCatalogVersion,poissonRatio,isotropicApproximation:true,applicability,allowExperimental:false}]}`. The shared method is `studioApi.applyCatalogMaterial` with the same single object. Use the returned catalog version, explicit user-assumed Poisson ratio and nonempty applicability conditions; experimental entries require explicit allowExperimental:true. GUI application also requires applicability. Catalog sources, measurement conditions and missing data remain in the snapshot. Application invalidates old evidence for `/material`, `/materialProperties` and their child pointers even if values match: status becomes unconfirmed, assumption null and confirmation removed. Retain old source/value/rationale/applicability for reconfirmation. Other evidence and analysisIntent remain; no confirmed evidence is invented. Existing nonlinear preset replacement behavior is inherited: check the resulting material model and required inputs before solving.

### Preview before committing semantic edits

Use studio_preview_edit({path,expectedRevision,operations,method?,size?,operation?,mode?}) for saved inputs or inspect-scope live previewEdit({expectedRevision,operations,options?,operation?,mode?}). The shared method is studioApi.previewOperations(operations,{expectedRevision,options?,operation?,mode?}). Preview clones input, applies the semantic batch and returns summary/preflight plus previousRevision, candidate revision, operationCount and changedPointers (at most 100, with total/truncated). It writes no file, starts no solver and returns neither full candidate nor operations. It may inspect a next configuration during active computation without changing the job; an intervening current-input edit causes conflict.

A valid command may return preflight.allowed:false; inspect diagnostics rather than treating preview success as physical validity. To commit exactly the reviewed candidate, send the same operations/original expectedRevision and expectedResultingRevision equal to preview.revision through edit or studio_edit_project. This optional resulting-version check does not grant edit scope or bypass busy/revision checks. Repository declarations currently list33 default/35 connector tools and91 live operations; earlier counts describe previous increments. Full P0/P1/P3 and physical validation remain unfinished.

Preview preflight is compact: diagnostics max50, requiredPointers max100, reportPage totals/truncation, omitted array values/long strings/deep or wide evidence. allowed/provisional still come from full inspection. Request existing preflight for full detail. The 65,536-byte UTF-8 cap applies to returned value JSON, not duplicated whole MCP RPC encoding; excess rejects with EDIT_PREVIEW_RESPONSE_LIMIT and leaves input unchanged. Browser normalization metadata distinguishes unnormalized candidate previousRevision from final revision and lists changedPointers/requiresReview. If requiresReview:true, inspect host defaults/display-unit/inactive-field changes before committing the final revision. The trusted GUI-shared normalizer is not wire-selectable; Node saved-file preview has no GUI conversion, so do not reuse a browser candidate revision across targets.

If a registered wrapper projects positional `args` as `string[]`, do not stringify numeric/record/array arguments to fit that declaration. Refresh the actual tool schema when possible, or deliberately use the documented local `callStudioTool` path and report the different environment. Raw MCP schema support does not prove the registered wrapper was refreshed.

Explicit planar `rotationDegrees` requires its matching `frame:{origin,u,v}` even for zero angles. Do not send only GUI rotation controls: these are rejected rather than silently selecting an unrotated plane. Existing frame-only planes and unrotated axis/position descriptors remain supported; refusal preserves input.

## Local mesh refinement from the current selection

Use semantic `addSelectedMeshRefinements({size,radius,baseSize})` through studioApi or the existing saved/live preview/edit operations. All three values are explicit mm: size is the local target, radius the influence radius, and baseSize the global target you intend to use on the later job. It does not set that job's size. Require finite positive values and size between 15% and 100% of baseSize.

Select actual current triangles/CAD faces first, then preview the transaction with `{method:"addSelectedMeshRefinements",args:[{size,radius,baseSize}]}`. It appends sampled selected-triangle centroids using the GUI helper (up to 80 per call, 160 retained total), preserves selection and existing refinements, and refuses empty selection. It does not infer loads/materials or establish mesh convergence. Retain the preview revision, then apply the same operations with expectedRevision and expectedResultingRevision; stale or invalid edits leave input unchanged. Saved MCP uses studio_preview_edit/studio_edit_project with a new outputPath; live MCP uses previewEdit/edit with edit scope. Discover the method-specific schema on those tools. Existing setMeshSettings({refinements:[]}) clears all local refinements deliberately. Confirm actual mesh density/convergence after meshing.
