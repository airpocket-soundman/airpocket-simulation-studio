## Result views and saved cases

### Configure saved time-history density

Use existing `setStudy` through the normal saved/live edit transaction for optional `thermalSnapshotCount` or `acousticSnapshotCount` (integers 2–61), and `thermalSnapshotBudgetBytes` or `acousticSnapshotBudgetBytes` (safe integers 1–67,108,864). Preserve the other study settings and revision guards. Thermal nodal history remains opt-in; omitted acoustic settings retain legacy stored times. These numerical controls change stored solved states, not the calculation time step, receiver trace density or physical validity. Both endpoints are retained. Requests beyond solved states or scalar-storage budget reduce the saved count with `snapshotInfo.warnings`; a budget unable to hold two frames is refused. The eight-byte-per-node-per-frame budget excludes JavaScript/container overhead, observation payloads, receiver traces and renderer copies; do not describe it as a peak-RAM limit. Reinspect the actual result's `snapshotInfo`/stored times before selecting frames or exporting. Display interpolation does not create additional solved states.

Prefer paired semantic MCP operations for implemented views/cases and the export jobs below for PNG/WebM. `getResultView` returns resultRevision, supported fields/display units and paged stored modes/times (limit <=50). When the displayed result carries validated time-history `snapshotInfo`, it also adds a bounded `snapshotStorage` summary (`requested`/`count`/`bytes`/`budgetBytes`, `unit:"byte"`, `bytesPerScalar:8`, `meaning:"stored-scalar-values-only"`, `excludes` for objects/rendering/observations/receiver-traces/peak-memory and `warningCount`), never the stored-step list, warning texts or physical arrays; inconsistent metadata is refused and legacy results omit the field. Do not read `snapshotStorage` as a peak-RAM guarantee. `setResultView({expectedResultRevision,settings})` supports field/layers, nonnegative deformScale, camera position/target/up/fov, modeIndex, acoustic/thermal frameIndex or exact stored timeSeconds (no arbitrary interpolation), and `{field,minimum,maximum}` colorRange (null = automatic). Use reported units: stress is displayed in MPa, temperature in degC. A different field resets automatic colors unless its new range is explicit. Capture/reapply state as JSON; case archives do not persist it automatically.

`probe` accepts optional expectedResultRevision and measures the displayed stored frame/mode, returning identity and assessment. Modes remain normalized shapes rather than dynamic response; deformation scale is visual only. Do not invent missing time frames or treat intermediate thermal retention as final-result playback.

`caseList` returns archiveRevision, compact IDs/revisions and metrics. Use `{caseId,expectedRevision}` for caseView/caseRestoreInput/caseRemove, add name for caseRename, or use `{name,expectedResultRevision}` for caseSave. Rename changes revision. External archive changes invalidate IDs; list again. Case display also restores saved input and therefore requires edit permission. Inspect scope can read, view scope changes settings, analyze scope saves and edit scope modifies/restores cases. Recheck state after a timeout before retrying any mutation. Chunked live case-archive transfers are described below. Bundling named views into case archives remains pending.

## PNG/WebM through the paired connector

Prefer `exportCapabilities` and semantic export jobs over browser code. Read capabilities first: WebM depends on browser recording support; MP4 remains unsupported. With view scope, call `startExport({requestId,expectedResultRevision,format:"png"|"webm"|"gif"|"png-sequence",animation:"orbit"|"deformation"|"time"|"slice",seconds})`; seconds is an integer 1..15 (default 5; not accepted for png-sequence). `png-sequence` is deterministic fixed-frame export: `frames` 2..120 (default 24), frame i rendered from the stored view state for index i of N (orbit/deformation phase i/N, time/slice i/(N-1); time needs N <= stored snapshots), returned as one STORE ZIP (`manifest.json` + `frame-NNNN.png`) with per-frame result revision, phase/angle/physical time, resolution and SHA-256; caps 4 MiB/frame and 24 MiB total are explicit refusals, cancel yields no artifact. The job freezes a copy of current view/settings and checks the result revision before rendering. Identical retained requests are idempotent; changed arguments need a new requestId.

Inspect scope permits exportCapabilities/exportStatus/exportArtifact. Poll `exportStatus({jobId})` to terminal state. Only completed jobs expose artifacts. Retrieve `exportArtifact({jobId,offset:0,length:65536})`, base64-decode data, follow nextOffset until null, concatenate bytes and verify totalBytes and SHA-256 against metadata (mimeType/name/sha256). Offset counts decoded bytes; length cannot exceed 65,536. No arbitrary browser scripts, arbitrary file paths or global filesystem access is needed. Jobs do not trigger downloads or persist output; save verified bytes only to a destination authorized by the user.

Use view scope for cancelExport/releaseExport; release retained output when finished. Default limits are 32 MiB total, four jobs and one active renderer including cancellation cleanup. Disconnect cancels connection-owned exports; late cancelled/released output is unavailable. Page exit loses output; case archives and restart recovery do not retain it.

## Portable named views

Use `namedViewList` (inspect) to read archiveRevision and viewId/revision/name/resultRevision. Read getResultView before saving. `namedViewSave({name,expectedResultRevision,expectedArchiveRevision})` (view) captures result settings/camera plus setup clipping/parts, field-defined units, ranges and selected frame/mode. Names are 1–100 characters, at most 16 views. No physical arrays or model are included.

`namedViewApply({viewId,expectedRevision,expectedResultRevision})` (view) requires the exact saved result revision, not another calculation's result. `namedViewRemove({viewId,expectedRevision})` requires view scope. Reinspect after conflicts/timeouts; do not reuse stale revisions blindly. Application failures attempt rollback.

`namedViewExport` (inspect) returns `{version:1,views:[{id,name,resultRevision,result,setup}]}`. Save JSON to a user-authorized destination, then use `namedViewImport({archive,expectedArchiveRevision})` (view) to transfer it back, replacing the entire current view list. Invalid schema, unknown keys, nonfinite values, bad cameras/ranges or duplicate IDs are rejected. There is no automatic localStorage persistence; use the case-view bundle below for combined transfer and export explicitly before page exit. Shared browser API: window.namedViewApi.list/save/apply/remove/export/import. The GUI panel offers equivalent save/restore/remove/import/export actions. Cross-result synchronization is unsupported.

Thermal stored-time selection accepts frameIndex or exactly matching stored timeSeconds, never both or arbitrary interpolated times. state.frameIndex remains null for compatibility; use physicalTimeSeconds/interpolated and timeSelection (stored-frames-only at stored times, viewer-slider-only for GUI interpolation). Generic/null frame patches preserve interpolation. Heat flux requires the non-interpolated final stored time. Localhost real-Chrome verification of this API addition is recorded below.

At an exact stored thermal time, `storedFrameIndex` identifies the displayed snapshot; it is omitted for GUI-interpolated times. Thermal frame metadata remains paged through `getResultView`.

Named thermal views capture and reapply an optional `thermalTime:{kind:"thermal",timeSeconds}` at an exact stored time; `state.frameIndex` remains null for compatibility. Measurement history/archives also support stored temperature frames, retaining display `physicalTimeSeconds`, `interpolated:false`, `timeSelection:"stored-frames-only"` and `storedFrameIndex`. Nonfinal samples contain temperature without flux; final samples include final heat flux. Saving an interpolated thermal named view or measurement is explicitly refused.
