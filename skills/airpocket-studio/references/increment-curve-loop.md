# Saved curve verification loop

Use this bounded synthetic workflow when verifying curve extraction through the local MCP server. It requires no browser pairing or real AI login. The public references are synthetic independent linear Tet4 solves, not measured data or plastic history. This loop does not establish browser download, general physical accuracy or public deployment acceptance.

From the selected checkout, start one retained `node scripts/studio-mcp.mjs` process. Use newline-delimited JSON-RPC over stdin/stdout: `initialize` with protocolVersion `2025-11-25`, then `notifications/initialized`, then `tools/list`. The initialized notification is required before tool calls. Discover `studio_increment_curve`; do not assume the connected server has the same tools as this checkout. If it is absent in the registered connector, explicitly state that this is the local repository stdio server.

1. Read `public/examples/increment-comparison-a.json` and `increment-comparison-b.json` as raw bytes and retain their SHA-256 values. Parse them into a new `{bundles:[A,B]}` input in a disposable output folder; do not edit the source examples. Call the discovered `studio_increment_curve` with absolute `path`, new absolute `outputPath`, `offset:0` and `limit:1`.
2. Unwrap `result.structuredContent.value` once. Require `kind:increment-curve-comparison`. Follow each curve's returned `page.nextOffset`, making read-only calls with no outputPath until that curve ends. Offsets are shared request arguments but independently clamped by each curve. Preserve curve IDs, revisions and ordering on every page. Do not duplicate already read rows of a shorter curve. Each reference has four rows and one failed gap; failed rows carry no measurement values. Successful last forces are A=20 N and B=40 N. Last extensions match because B has twice the stiffness. Read units from the response: mm, N, Pa and dimensionless strain.
3. Read the saved artifact-bundle JSON. For each of `csv`, `json`, `svg`, encode that exact string as UTF-8 and compare its byte length and SHA-256 with the response artifact descriptor. Also compare complete saved-file bytes/hash with outputBytes/outputSha256. Write the three strings as separate files and read them back to verify the same hashes. Their JSON is the derived comparison, not reusable raw solve input.
4. Check SVG has no script, event attributes or external URL references. Its two panels must retain A/B identity and failed gaps. Use the returned row metadata rather than guessing data from pixels. CSV has one header and eight data records for these references; parse quoted CSV fields rather than splitting commas blindly.
5. Deliberately add a self-reported `svg` field to a separate copy of the raw wrapper. A new outputPath must be refused and must remain absent. Reusing the successful outputPath must also refuse without changing its bytes. Re-hash the two original reference files and require equality with step 1. Input project state is never accessed by this saved-file tool; this does not claim equality of an open browser project's revisions.
6. Close MCP stdin, observe process exit 0, and retain a sanitized report with source/runtime identity, all hashes, row/failed counts, refusal results and explicit limitations. Never store pairing credentials. Distinguish independent execution of this final recipe from a run that revised it while operating.
