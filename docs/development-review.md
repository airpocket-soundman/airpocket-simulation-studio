# 開発方針・仕様・計画の整合性レビュー

確認日: 2026-10-14。[English](en/development-review.md)

対象はローカル作業ツリーの製品方針、エージェント操作、ビューア仕様、ロードマップ、構成、ブラウザ実行、ソルバー、検証、自動化、README、個別機能仕様と`src/progress.json`。`package.json`、`src/main.js`、`scripts/studio-mcp.mjs`も照合した。外部製品の現行仕様や公開サイトの再検証は今回の対象に含めない。

## 指摘と対応

| 指摘 | 根拠と影響 | 今回の対応・残作業 |
|---|---|---|
| ロードマップが実装より古い | STEP・Worker接続を次の着手点としていたが、v0.43では解析・MFEM・音響・出力まで存在 | 旧フェーズを現状基盤とP0〜P6の計画に置換。完了済み機能を再開発する順序を解消 |
| ソルバー候補が必須実装に見える | 旧計画は構造CalculiX、熱Elmer、流体OpenFOAMを段階成果に指定。実際はAirpocket/MFEM、他候補は未移植 | 追加移植を統合例題の前提から外し、候補と現在の対応をソルバー文書で明示 |
| UI技術の記述が不一致 | 日本語の構成・ブラウザ仕様はTypeScript/Reactを記載。package.jsonとmain.jsはJavaScript/Vite/Three.js、英語構成もvanilla JSと記載 | 現状へ修正。React/TypeScript移行を必須作業にしない |
| ネイティブ版の位置付けが曖昧 | 製品方針はWASM/ネイティブ両版を目標、構成は将来の任意拡張。native-solvers.mdのMFEMはWASM | ブラウザ優先、ネイティブは別導入の後続目標と整理。P6で機械語版を実証し、Node/WASMと区別 |
| エージェント全機能操作と現在のMCPの差 | 目標はライブ状態・設定・出力まで。現MCPは6ツールで保存JSON中心、ブラウザを変更しない | P0で操作対応表、P1で入力作成、P3で接続、P4でビューア操作を計画。目標レベル達成済みとは扱わない |
| 進捗の歴史的説明が現在の能力と混在 | REG1はCAD分割未対応、BC1は計算なし等の当時の記録。後続実装と単独では食い違う | 公開履歴は保持。ロードマップで読み方を明示。P0で現行能力表を整備し、進捗の説明更新・後続タスク参照を検討 |
| 造形機能の最終段階方針と実装中作業 | PRINT2はbuilding、直交異方性基盤が存在する一方、造形解析は未完成 | 既存基盤の区切りと回帰確認を維持し、新規造形拡張より共通API・入力・実行準備を優先 |
| ブラウザ内処理と将来リレーのデータ境界 | 現状はモデル送信なし。将来のLLM/リレー接続では情報の共有が発生し得る | 現状と将来契約を分け、P3前に許可・範囲・失効を決める。接続方式は未決定のまま保持 |
| 日英ロードマップの範囲差 | 英語のみ造形の最終任意段階を列挙。新しい方針と旧段階が混在 | 日英を同じP0〜P6、判断ゲート、バックログ、完了判定へ同期 |

## 判断

ローカル計算・ブラウザからの導入・共通API・設計反復という製品の主軸は一致している。主な問題は旧計画の陳腐化、候補と実装の混在、将来仕様と現在能力の区別不足である。接続方式、スキーマ互換性、性能目標、Rustの採用、SolidCraft連携契約は未決定であり、決定済みの仕様に置き換えず[開発計画](roadmap.md)の判断ゲートへ移した。

今回の変更は文書整備のみ。既存の未コミットの製品方針・エージェント/ビューア仕様・ボード実装を保持し、進捗ステータスとリリース実績を変更していない。機能の正しさや公開版との一致を新たに保証するレビューではない。
