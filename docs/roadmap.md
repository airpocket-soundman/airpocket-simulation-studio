# 開発計画と受け入れ条件

[English](en/roadmap.md)

更新日: 2026-10-14。製品方針は[product-direction.md](product-direction.md)、操作仕様は[agent-operation.md](agent-operation.md)、表示・出力仕様は[result-viewer-direction.md](result-viewer-direction.md)を参照。本書を今後の実装順序と完了判定の基準とする。仕様案は実装済みを意味しない。

## 最優先の製品原則（2026-10-14確定）

最大の差別化要因は、ユーザー自身のLLMが専門SKILLを通じて本アプリの全機能を自由に組み合わせ、解析と設計反復を進められることである。独自AIを設計・提供してAIサブスクリプションへ誘導する構成を製品の前提にしない。LLMの選択・契約・実行環境はユーザー側にあり、本アプリは共通API、MCP、専門SKILL、検査と結果の証跡を提供する。

最優先事項は、全利用者機能のAPI化とMCP対応、専門SKILLの継続育成、中間結果をLLMへ返すパイプラインの整備である。準備・メッシュ品質・反復/残差・時間ステップ・暫定測定値をジョブIDと入力版に結び付け、要約と詳細成果物参照を取得できるようにする。中間の場を提供できないソルバーは制限を明示する。LLMが観測して次の設定を準備できても、実行中スナップショットを変更しない。

GUI機能を追加する際は、意味的API・MCP・状態/診断・SKILLでの使い方と検証例を同じ作業として扱う。SKILLは現行能力、単位、物理的前提、失敗からの修復、暫定/最終結果の区別を教え、モデルやソルバーを黙って変更しない。API網羅率、MCPだけでのタスク完了率、中間情報の観測と再設定、SKILLによる例題の再現性を受け入れ指標とする。

実装順序はP0/P1を入口とし、P3の中間結果・共通ジョブとP4の既存全機能API/MCP化を最優先で進める。専門SKILLの更新と例題検証を各段階へ含める。P2はこの経路を支える必要範囲で進め、追加の可視化表現・物理モデル・造形拡張より優先する。P4の新しい表示機能は既存機能のAPI/MCP化と分けて後続にする。

## 現在地と管理方法

公開基準はv0.43。公開時の検証記録は242テスト・配信物26項目・画面42項目であり、今回の文書整備で再実行した数ではない。STEP、領域指定、共通API、体積メッシュ、Airpocket構造・熱・限定流体・音響・固有振動、MFEM線形構造WASM、ケース比較、PNG/WebM、保存JSON対象のMCPを基盤として利用する。制限は[解析ガイド](analysis-guide.md)と個別仕様を優先する。

`src/progress.json`は既存タスクと公開実績を管理する。古いタスクの説明は当時の範囲を含むため、単独で現在の能力一覧としない。以下のP0〜P6は進捗JSONに登録した計画識別子である。着手する作業単位を追加し、依存先、受け入れ条件、実装・検証の証跡を結び付ける。計画の追加だけでreleasedへ変更しない。

既存のREG2・PRINT2は実装中として保持する。REG2の未解決領域を実行前に拒否する基盤はP1に利用する。PRINT2の直交異方性基盤と造形解析の完成は区別し、基盤の保存・拒否・回帰確認を区切りとして、追加の造形機能よりP0〜P2を優先する。

## 既存バックログと拡張の扱い

- MESH1・REG2・CFDPORT1: 既存の平面・円筒分割と一般曲面・任意開口の未完部分を区別。P1/P5に必要な範囲から進める。
- CFD1・CFDMESH1・CFD2・CFD3: 限定流路/Stokesを一般Navier–Stokes・乱流・圧縮性・多相流と区別。追加モデルごとに参照解・収支・収束・資源測定を要求する。
- COUPLE1・COUPLE3・COUPLE4B・COUPLE5、CONTACT1、FAIL1: 既存の限定連成・材料・疲労・破壊評価を維持し、一般連成・接触・き裂進展等は個別検証後に公開する。
- PRINT2: 3MF/G-code読込・表示と積層/インフィルの構造解析を分離。実測校正なしに造形物の精度を保証しない。造形拡張は標準解析とエージェント反復を成立させた後の任意機能とする。
- CalculiX・Elmer・Code_Aster・OpenFOAMは採用候補。既存のAirpocket/MFEMを使うP0〜P5の前提に追加移植を置かない。流線・粒子・等値面等はビューア仕様の順で段階追加し、表示追加を解析モデル追加と扱わない。

## モジュール単位の並列開発

LLM向け統合を優先しつつ、共通契約を固定した独立モジュールは並列に進める。計画全体の完了と先行モジュールの完了を区別し、検証範囲・未接続箇所を進捗へ記録する。

- AGENTEDIT1: 保存入力の原子的編集と版照合。P1の先行実装であり、STEP作成・根拠スキーマは別途必要。
- AGENTJOBS1: Node CPUジョブ・中間結果パイプライン。P3の先行実装であり、ライブブラウザMCPと再起動越し復元は別途必要。
- PROCESSISOLATION1: Node解析を同一実行ファイルの子へ分離する任意経路。中間結果APIとMCPを維持し、異常終了・キャンセル・タイムアウト後はcloseを待ってから資源終了を確定する。V8根治とは分離して検証する。
- CFDINTERNAL1: 内部低Re流路の速度境界アダプターとP1/P2参照検証。一般流体やUI/Worker接続を完了扱いしない。
- NATIVEPROOF1: Linux CIで実ホストMFEMと同一C++のWASM比較が成功。固定棒5条件・不正入力8件を確認。任意保存入力や製品ネイティブバックエンドは未対応。

ソルバー担当は個別アダプターと参照例題、流体担当は領域/境界/計算/メッシュの独立部、統合担当は共通API/MCP・診断・結果契約を受け持つ。変更範囲を分け、最終的に保存互換性と共通API・ブラウザ実行で統合検証する。先行研究を理由にLLM向け開発を待たせない。

## 後続タスク: 既存CAEのUI研究と改良

LLM向け機能（P0・P1、P3の中間結果パイプライン、P4の全既存機能API/MCP化と各段階の専門SKILL整備）を優先する。次のタスクはそれらの後続として進捗管理へ登録する。

- **UIRESEARCH1**: FreeCAD FEM、PrePoMax、SALOME/ParaViewや商用CAEの公開資料を対象候補に、形状取込、モデル/解析ツリー、領域選択、材料・条件、ジョブ監視、診断、結果比較・出力のUIを研究する。調査時の対象・版・資料URL・確認日と、実際に確認した操作と推測を記録する。共通例題で初心者の操作負担、誤設定からの復帰、LLMとの協働を比較し、優先順位付き改善案・画面案を作成する。依存: P0・P1・P3・P4。
- **UIIMPROVE1**: 研究結果を基に段階的にUIを改良する。同一例題で変更前後の完了状況・操作数・復帰のしやすさを比較する。新しい利用者機能は意味的API・MCP・専門SKILLと同時に整備し、日英・狭い画面・キーボード・保存復元・公開画面を確認する。依存: UIRESEARCH1。

研究と改良は未着手であり、既存CAEの優劣や採用するUI方式はまだ決定しない。

## 全段階の完了判定

1. 対応範囲を限定し、入力作成・検査・実行・結果取得・保存復元を通す。入力検査、数値収束、物理精度は別々に記録する。
2. 参照値、許容差の根拠、実測誤差、メッシュ、エンジン・モジュール版、入力スナップショットを保存する。
3. 共通APIとMCPの検証に加え、ブラウザ対象機能はPagesの実行・画面確認を行う。Node配信物チェックは描画・実GPUの代替にしない。ネイティブ専用機能はその実行環境で確認する。
4. 不正入力・失敗・中止後の状態保持、資源解放、日英表示と文書リンクを確認し、進捗へ証跡を登録する。
