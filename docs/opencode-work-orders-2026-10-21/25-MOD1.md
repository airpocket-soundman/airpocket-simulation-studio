## 番号付き実装と受入

1. serialize/apply の thermal/acoustic SnapshotCount/BudgetBytes に限定して helper 化する。現在の normalize/HTML value sanitization の順序を維持する。
2. thermal transient の count=9 frames、budget=2 MiB → 2097152 bytes を確認。acoustic transient の count=7 frames、budget=0.5 MiB → 524288 bytes も確認する。復元値は元の MiB。
3. count=0 は field 省略、budget 空欄は省略。transient=false と structural で該当保存 field が入らない。空文字/null/不正文字の既存変換・拒否を特性 test で保持する。
4. 「最小2枚」や budget 制限は既存 plan/validation の責務。変換 helper 内で clamp/default/新拒否を導入しない。秒/ms/µs 変換や物理計算を変更しない。
5. JSON roundtrip、raw controls 不変、study 以外の候補 field 保持を test。旧保存入力で新 field が無い場合の既定動作を維持する。
6. 差分が読みやすくなる1単位だけ納品。既に同等 helper が入っている場合は追加再分離せず、その実装/testを示して既済と報告する。
7. Node 純粋変換の検証と実 Chrome 復元の検証を分ける。Chrome 未操作なら GUI 回帰確認済みと書かない。
