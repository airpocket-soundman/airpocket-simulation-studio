# 34 P3 — 同時startによる永続digestの誤帰属を修正する

## 前提・読む順
1. [00-COMMON.md](00-COMMON.md)の「元PRを修正する7件の特別手順」を優先する。
2. 修正対象は#131、レビュー固定head `f0c9accf000731193fd279e86e7aef4321283558`。
3. `gh pr view 131 --json headRefName,headRefOid,state`で現headを取得する。
4. 他人の`studio-opencode-p3`は再利用せず、取得headから自分のrepair branch/treeを作る。
5. `scripts/analysis-job-service.mjs`のstartupDigests/onRecord/start/release。
6. `scripts/analysis-job-store.mjs`、`src/analysis-jobs.js`、`tests/analysis-job-service.test.mjs`。

## 確定反例
固定headのservice:104はjobId未確定のrequestId slotを別startで上書きできる。
同requestIdのA(valid input)とB(missing input)をPromise.allSettledで同時に呼ぶ。
Aはfulfilled/Bはrejectedでも、Aの永続record.startupDigestがBのdigestになる。
レビュー実測：matchesA:false、matchesB:true。再起動後のRESTORED/CONFLICTが逆転する。
この反例を先に回帰test化し、修正前の失敗を確認する。

## 変更してよい場所
- `scripts/analysis-job-service.mjs`：in-flight予約とjob所有者へのdigest結合。
- `tests/analysis-job-service.test.mjs`：同時startと拒否/後片付けの回帰。
- 必要時のみ`tests/analysis-job-store.test.mjs`、`tests/mcp-restored-request-id.test.mjs`。
- `docs/evidence/<実日付>-opencode-p3-race-repair.json`。
- store schema変更や新tool追加は不要。共有docs/progress/Skillは触らない。

## 実装順
1. A/Bは同じrequestId `race-01`、operation mesh、size5で作る。
2. Aのinputは既存合成box fixture、Bは存在しない絶対path、outputもA/B別にする。
3. workerは注入で即座に明示失敗させてよい。解析成否ではなくstart/record帰属を検査する。
4. async stat/read前から要求ごとの所有token/reservationを固定し、別要求が上書きできなくする。
5. digestをrunning record生成へ渡す際、共有requestId最新値だけを参照しない。
6. Bの拒否/cleanupでAの予約・digest・jobIdを削除/変更させない。
7. 同一条件の同時retryは既存idempotencyを維持し、異条件は明確に拒否する。
8. 全要求失敗時の未所有予約は解放し、requestIdを変える失敗でMapを無限成長させない。
9. release、close、成功/失敗の終端まで所有関係を追い、旧record互換を保つ。

## 数値入り受入
- A/B同時要求でaccepted jobのrecord digestは必ずA。B digest一致は0件。
- B先行/後行の2順序と、read待機を制御したfixtureで順序に依存せず確認。
- 同一条件の同時2要求は同じjobId、worker起動は最大1回。
- 再起動後A条件はANALYSIS_JOB_REQUEST_RESTORED、B条件はCONFLICT。
- 旧digestなしrecordは従来RESTORED。復元後worker起動0回・resultAvailable:false。
- 失敗だけの要求を32件処理後も、同requestIdの正規start/releaseが可能。
- 生pathや結果配列を永続recordへ追加せず、8192bytes/256records制限を維持する。

## 対象試験・停止
- `node --test tests/analysis-job-service.test.mjs tests/analysis-job-store.test.mjs tests/mcp-restored-request-id.test.mjs tests/analysis-jobs.test.mjs`
- `npm run check:contracts`、`git diff --check`。
- missing inputを実在に変える/同時呼出しを直列化することで反例を消さない。
- 元PRheadが進んだら差分再確認。知らないdirtyやFF拒否では停止しforceしない。

## 証拠・納品
修正前後のA/B digest照合、制御した並行順序、worker起動数、再起動判定、test実数を保存。
元headからの修正commitを、取得した既存head branchへ通常FFpushして#131を更新する。
未mergeなら重複PR禁止。既mergeなら00の特別手順で最新mainから修正PRを作る。
反例と既存idempotency/復元互換が通ればこの単位は完了。P3親は未完維持。
