# WebGPU計算（構造・試験版）

[English](en/webgpu.md)

計算エンジンから「WebGPU + CPU補正」を選択すると、線形構造の疎行列・ベクトル積をWebGPUのcompute shaderで実行します。CSR形式に変換し、係数と入出力はfloat32。PCGのベクトル更新と内積はCPUです。メッシュ、剛性組立、後処理もCPUで行い、全ソルバーをGPUで実行する方式ではありません。

GPUで初期近似を求め、元のfloat64剛性で残差を測ります。初期残差が1%を超える場合はCPUへ戻します。WASM CPUで補正し、自由度の最終残差が2e-8以下であることを確認してから結果を返します。GPUがない、デバイスを作れない、バッファ上限、未収束、精度条件に不合格の場合はCPU計算に切り替え、その理由を表示します。GPUの起動待ちは8秒、全ワーカーは120秒上限です。ワーカー全体の時間切れは結果を返さず中止します。

Intelの実GPUで、0.04 mm・反力100 N、圧力重力0.040008 mm・100.04 N、局所座標の指定変位±100 N、428→737→1156要素の適応ループを検証しました。最後の自由度残差は約1e-9以下です。保存したGPU結果を再計算せず表示し、使用経路と精度・時間の記録を残します。

今回の小さな指定変位例ではGPU経路723.7 ms、WASM CPU49.2 msでした。デバイス準備・転送・CPU補正があるため、速くなる保証はありません。既定はWASM CPUです。熱、音響、流体のGPU経路は未対応で、選択できません。別ブラウザやモデル規模全体の性能調査はPERF1の残作業です。

`analysisApi.checkGpuEnvironment()`で使用可否、実GPU/ソフトウェア代替とデータ上限を確認できます。ペア済みブラウザはinspectスコープの`checkGpuEnvironment`操作でも同じブラウザ診断を実行できます。返却値は実行時観測で、操作の宣言とは別です。NodeのGPU能力とは混同しません。`analysisApi.analyze({method:'webgpu-pcg'})`で同じ計算経路を実行できます。Nodeの回帰テストではCSR、float32近似、CPU補正、CPU切替、実ワーカーの切替経路を検証します。実WGSL演算はブラウザのGPUで別途確認しました。Nodeテストで実GPUを検証したとは扱いません。

API参照: [W3C WebGPU仕様](https://www.w3.org/TR/webgpu/)。
