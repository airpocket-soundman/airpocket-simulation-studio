# 進捗推移と製品達成度の推定

[English](en/progress-dashboard.md)

開発管理ボードの「進捗推移・達成度」画面の仕様。観測値（Git履歴の実測と作業数）と推定（製品全体の達成度）を分けて表示する。

## 作業数の推移（観測）

- 元データは`src/progress.json`を変更した実際のGitコミット。ビルド時に`scripts/progress-history.mjs`が`git log`と`git show <commit>:src/progress.json`だけを使い、コミット時刻（`%cI`）ごとに6状態（待機・実装中・検証中・修正中・検証済み・公開済み）の件数を記録する。補間・推測・合成した点は作らない。
- タスクの追加・削除は、直前の記録点とのID集合の差として記録する（各点で最大25件のIDと実件数）。IDの付け替えは追加+削除に見える。
- 浅いclone、点数上限（1000）、読めないコミット（ファイルなし・過大・不正なUTF-8/JSON・状態や重複IDが不正）、コミット時刻の逆転は`completeness`と`skipped`に記録し、画面に注意として表示する。読めないコミットは点にしない。
- 成果物`progress-history.json`は有界（2 MB、点1000、スキップ200、スナップショット2 MB、合計256 MB）。`validateProgressHistory`が構造・件数合計・「合計=前回の合計+追加-削除」を検証し、不整合は修復せず拒否する。
- ビルド順は`build-progress-history.mjs`→`build-manifest.mjs`。履歴は`runtime-manifest.json`の`files`にバイト数とSHA-256で登録される。CIは`fetch-depth: 0`で取得し、`PROGRESS_HISTORY_REQUIRE_COMPLETE=1`により浅い取得では失敗する。
- ボードは公開候補と同じ読み取り（`fetchPublishedProgress({includeHistory:true})`）で、前後2回のmanifest確認の間に履歴を取得し、バイト数・SHA-256・スキーマ・`head.revision`・`head.progressSha256`が検証済み候補と一致した時だけ表示する。失敗しても進捗の検証結果は変えず、履歴を「利用不可」と理由コード付きで示す。履歴導入前のmanifestは利用不可（`PUBLISHED_HISTORY_ABSENT`）。同梱の初期記録には履歴がない。
- 凡例（状態の表示切替）、コミット選択スライダー（矢印キー）、グラフのクリック、詳細、全記録点の表（折りたたみ）を提供する。色だけに依存せず、線種とマーカー形状も状態ごとに変える。欠落がない時のみ階段線を描く。

## 製品全体の達成度（推定）

- 目標は`docs/roadmap.md`のP0〜P6と既存バックログ・共通完了判定・公開マイルストーン6ゲート。固定の13項目（重み合計100）を`src/product-estimate.js`の`PRODUCT_RUBRIC`に持ち、各要素に作業IDと根拠文書を結び付ける。
- 重みはロードマップの優先順位に基づく判断値である（公開前優先のP0・P1・P3・P4と公開ゲートを重く、P2・P6・公開後続を軽く）。統計的な根拠はない。
- 要素の達成度は、紐づく作業の状態点の（平均+最小）÷2。状態点は低/中心/高の3通り（`STATUS_CREDIT`）。公開済みの中心点は0.9で、範囲全体が閉じた時だけ1。作業が紐づかない要素は「未知」として中心0（楽観側のみ0.2）。マイルストーンのゲートは表示候補と一致する`verified/passed`証跡と`status: complete`が揃う時だけ満点で、作業状態では閉じない。
- 範囲が完了していない間（未知の要素、未公開のP0〜P6、未完了の項目、マイルストーン未完了）は表示を99%以下に制限する。公開済み作業の割合は観測値として別に表示し、推定には使わない。作業の追加・細分化は推定を変えない。
- 限界: 作業状態は自己申告で証跡を再検証しない。完了ゲートは記録された候補リビジョンについての判定。数値収束・物理精度の達成度ではなく、完了日や工数は予測しない。

## 確認方法

`tests/progress-history.test.mjs`（抽出・スキーマ・上限・実git）、`tests/product-estimate.test.mjs`（採点表・計算・範囲）、`tests/published-history.test.mjs`（候補固定の読み取りとmanifest）。配信物は`npm run test:published -- --local`の`progress-history-candidate`で照合する。画面の表示・操作は実ブラウザで別途確認する。

レビュー修正: 履歴の欠落が1件でもある場合は、未知区間の前値補完を避けるため連続線を描かず確認済みの点だけを示す。WindowsのGit CRLF変換だけは同一内容として許可し、表示する実bytesのSHAへ履歴を固定する。それ以外の未コミット差分は拒否する。ゲートの満点は表示候補と一致するverified/passed証跡が条件。未知の受入要件は、採点表の版を更新して証跡を持つ作業へ紐づけるまで未完了とする（固定重み合計100を維持）。MCP studio_progressのincludeEstimate/includeHistoryは任意で、既定応答は変更しない。

## 公開状態の反映と監査

CIの成功やmainへのマージだけでは、タスクは自動で公開済みにならない。公開後に、そのタスク固有の受け入れ条件・証跡・配信リビジョンへの実装の包含を照合する。満たした検証済み項目は、証跡を付けて公開済みへ更新するPRを作る。未確認条件のある項目や、計画の一部分だけを実装したP0〜P6・MOD1は保留する。別タスクへ明示分離した公開接続などの要件を、すべての機能へ重複して課さない。

状態反映が遅れた分を一括監査すると、時系列の公開済み件数がまとまって増える。その増分は監査時点の状態訂正であり、同じ時間に新機能を実装した件数や開発速度ではない。実際のGit履歴は書き換えず、監査記録に判断理由と元の公開証跡を残す。

既存の165項目を直近の公開証拠と照合し、実時間WebMの背景タブ停滞（EXPORTBACKGROUND1）と原因未確定の接続reset/ページ初期化（BROWSERRESET1）を独立した未着手として追加しました。件数増加は新しい残作業の計上であり、完了増加ではありません。総数167・待機22、公開済み128など既存状態と製品達成度の固定重みは維持します。比較の一般形状/GUI保存・公開HTTPSの他権限・性能計測は既存親に残し、重複カードを作りません。新項目だけの完了で親や公開ゲートは閉じません。AGENTINPUT1の古い最新記録を現在の診断範囲へ置き換え、過去の試験記録は受入欄に履歴として保持します。
