# 16 P1 — 球面領域入力の単位と由来を点検で復元できるようにする

## 最初に読む
1. [00-COMMON.md](00-COMMON.md)、15-P0のpointer契約。
2. `src/project-input-inspection.js`のunitFor、provenance再帰処理。
3. `src/spherical-region.js`、`src/semantic-operation-schema.js`の球面入力仕様。
4. `tests/project-input-inspection.test.mjs`、`tests/spherical-wiring.test.mjs`。
5. `src/studio-api.js`のinspectInputと保存project経路。

## 今回の受入単位
球面selectionと条件に保存された同じ寸法について、点検結果の値・単位を一致させる。
現sourceでは条件のradius等の単位はあるがtoleranceが抜けている。最初に再確認する。
トップレベル球面selectionとprovenance値も含めて同じ既知寸法契約へそろえる。
既存snapshot count/budgetの単位、入力拒否、由来保存を作り直さない。
球面toleranceは表示mesh照合用であり、CAD精度保証と説明しない。

## 触れる場所
- `src/project-input-inspection.js`：既知球面descriptorのunit解決。
- `tests/project-input-inspection.test.mjs`：selection/condition/provenanceの値入りfixture。
- `tests/spherical-wiring.test.mjs`：必要な保存→点検の回帰だけ。
- 型変更が必要なら既存inspection型を検索して最小更新。
- 実測証拠JSON一件。solver/CAD生成/schemaを緩めない。

## 番号順に実装
1. selection/conditions/provenanceの実JSON pathと保存対象を確認する。
2. 既存球面unit分岐を共通小関数にし、未知pathへ単位を推測しない。
3. center/radius/toleranceはmm、axis/referenceは1、4角度はdegを返す。
4. mesh index、exactCad、未知キーへ物理単位を付けない。
5. 配列全体と各要素のunit挙動を既存inspection契約にそろえる。
6. provenanceのvalueは既存参照pointerを通じて同じunitを解決する。
7. source/conditionをexport→reloadして同じ点検値になることを確認する。
8. 単位を得る目的で入力値やprovenanceを変更しない。

## 値入り受入
- radius10、tolerance0.01、center[0,0,0]はmm。
- axis[0,0,1]、reference[1,0,0]は無次元1。
- latitudeMin=-30、latitudeMax=30、startDegrees=315、sweepDegrees=90はdeg。
- 条件forceの値123はNのまま、球面の値と混同しない。
- selectionとcondition内の同じ球面fieldでunitが一致。
- provenanceが参照するradius/toleranceも同じ値・unitを保持。
- 存在しないpointer、未知fieldは既存のmissing/unknown契約を維持。
- 点検前後のproject revision・export JSONが完全一致。

## 対象テスト
- `node --test tests/project-input-inspection.test.mjs tests/spherical-wiring.test.mjs`
- `npm run check:contracts`
- `git diff --check`
- spherical-wiringがnative依存の場合、既存cacheを使い実行範囲を記録する。
- missing runtimeをskip成功と偽らず、対象だけ実行不能として報告する。

## 停止・依存・証拠
- provenanceの構造を推測してfixtureを作らず、既存テストの実保存形式を使う。
- 正規の球面条件がreloadできない場合はunit表示で覆わず停止し原因を分離。
- 後続agentの入力監査に使えるが、全入力完全監査を完了扱いしない。
- 証拠はSHA、pointer/value/unit対応、保存往復、test実数と未実施を含める。
- P1親の全物理入力/provenance受入は未完維持。新精度保証を広告しない。
