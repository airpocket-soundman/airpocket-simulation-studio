# 18 P4 — PNG/GIF出力を独立に読み戻して照合するCLI

## 最初に読む
1. [00-COMMON.md](00-COMMON.md)。
2. `src/visual-export-jobs.js`のmanifest、sha256、totalBytes、resolution。
3. `src/visual-export.js`と実際のPNG/GIF encoderの参照先。
4. `tests/visual-export-jobs.test.mjs`、`tests/visual-export.test.mjs`、`tests/visual-export-fixed-frame.test.mjs`。
5. 既存verifierを`rg verify scripts tests`で探し、同等品があれば拡張する。

## 今回の受入単位
既存exportのmanifestとartifactを、別CLIからidentity/容器headerだけ読み戻して照合する。
最初は単一PNGとGIF。ZIP/WebM/PNG sequenceは明示的にunsupported。
GIFのframe数・duration・画素・物理結果の正しさはこのCLIでは保証しない。
既存export job/manifest/SHA検証は再実装しない。独立readbackを足す。
P4全体の操作・出力保証が完了したとは書かない。

## 触れる場所
- `scripts/verify-export-artifact.mjs`（新規、既存同等品があればそちら）。
- `tests/verify-export-artifact.test.mjs`（新規）。
- 既存CLI利用説明の該当節、sanitized証拠JSON一件。
- encoder、viewer、solver、manifest versionの変更は原則不要。

## 番号順に実装
1. 実manifestをfixtureから確認し、schemaVersion1の必須fieldを固定する。
2. `--manifest`と`--artifact`の明示pathを受ける。拡張子だけで形式判定しない。
3. 読む前に上限を確認：manifest64KiB、artifact100MiB、通常fileのみ。
4. JSON/型を検査し、実byte長とSHA-256をmanifestへ照合する。
5. PNG signature/IHDR、GIF87a/89aとlogical screen dimensionsを読み取る。
6. manifest format/mimeType/containerの実契約と寸法を一致確認する。
7. stdoutへ構造化report、任意`--report`には新規fileのみ書く。入力を上書きしない。
8. 成功exit0、照合不一致/不正/unsupportedは非0にする。
9. reportにidentityVerified/containerHeaderVerified/frameCountVerifiedを区別する。

## 値入り受入
- 既存encoder由来2×2 PNGと640×320 GIFがbyte/SHA/寸法一致で成功。
- GIFのframeCountVerifiedはfalse。24framesをheaderから証明したと書かない。
- artifact1byte改変、1byte切詰め、manifestのSHA変更、幅1違いを各拒否。
- 空file、不正JSON、100MiB超artifact、64KiB超manifestを各拒否。
- ZIP/WebMは黙って成功せずunsupported。任意JSONをmanifest扱いしない。
- report pathが入力と同じ、既存reportありの場合は入力/既存file変更0回。
- 正常reportに実totalBytes、64桁SHA、実width/heightを残す。

## 対象テスト
- `node --test tests/verify-export-artifact.test.mjs tests/visual-export-jobs.test.mjs tests/visual-export-fixed-frame.test.mjs`
- `git diff --check`
- テスト内CLIは別Node processでexit code/stdout/stderrとfile不変を確認。
- native解析やブラウザexportをこの単位のためだけに再実行しない。

## 停止・依存・証拠
- manifest形式が想定と違えば実producerに合わせる。fixtureを捏造して通さない。
- header検証だけを完全decodeや視覚検証と呼ばない。
- ZIP/動画検査は後続別単位。今回の受入を無制限に拡張しない。
- 基準SHA、fixture出所、成功/改変拒否、コマンド/test実数を証拠へ。
- P4親は未完維持、公開HTTPS/Skill一巡の代替証拠にはしない。
