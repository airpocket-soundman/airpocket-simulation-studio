# 14 MOD1 — 解析オプション読取りの境界を小さく分離

## 最初に読む
1. [00-COMMON.md](00-COMMON.md)を読み、独立作業treeと基準SHAを確定する。
2. `src/main.js`の`currentAnalysisOptions`、`runAnalysis`、`createAnalysisPreflightUi`呼出し。
3. `src/ui/study-form-ui.js`、`src/ui/discipline-controls-ui.js`、`src/module-layers.json`の層登録を確認。
4. `tests/ui-analysis-preflight.test.mjs`、`tests/example-study-reset.test.mjs`、`tests/module-boundaries.test.mjs`。

## 今回の受入単位
GUIの解析前チェックと実解析が使うオプション読取りを、DOMに直接依存しない関数へ分離する。
既存の共通`currentAnalysisOptions()`自体を二重に作らない。
MOD1全体、React移行、全TypeScript化、solver変更は範囲外。
後続15-P0の診断表示が同じオプションを使える状態を保つ。

## 触れる場所
- `src/main.js`：既存関数の委譲とimportだけを中心に変更。
- `src/ui/analysis-options.js`（新規）：フォーム値からoptionsを返す純粋関数。
- `tests/ui-analysis-options.test.mjs`（新規）。
- `tests/ui-analysis-preflight.test.mjs`：同一options利用の回帰を必要箇所だけ追加。
- module層定義の実ファイル：`rg --files | rg module-layers`で確認し新UI module登録。
- 証拠JSON一件。その他docs/progress/Skillの共有変更は担当者へ提案する。

## 番号順に実装
1. 現在の8項目の読取り、Number変換、百分率変換、既定値を一覧化する。
2. キー数が変わっていたら現在sourceを正とし、一覧と差分理由を残す。
3. 要素参照の取得はmain側、値の変換は新関数側へ置く。
4. 空文字のNumber変換やNaNを勝手に補正せず、既存の拒否経路へ渡す。
5. preflightとrunAnalysisの両方を同じwrapper経由のまま接続する。
6. 古い局所関数・同等moduleがあれば拡張し、新規の重複を作らない。
7. DOM実行順、reset/load、materialDirty、revision guardを保持する。

## 値入り受入
- size `5`、rounds `3`、elements `10000`、seconds `60`を正確にNumber化。
- tolerance `2.5`%は`0.025`、stressTolerance `4`%は`0.04`。
- adaptive false/true、method文字列をそのまま保持。
- 入力objectはdeepEqualで変更なし、出力は呼ぶたび別object。
- 同じフォームのpreflight/runでoptions全キーがdeepEqual。
- 空文字、非数、0、負値の扱いは変更前と同じ。物理合格の意味を追加しない。

## 対象テスト

- `npm run check:contracts`
- `git diff --check`
- full試験・公開は00-COMMONの統合手順へ委ねる。

## 停止・証拠・親状態
- source構造が違う場合は関数/呼出し検索を先に行い、単なる行番号置換をしない。
- reset/loadのassertを削除して通さない。既存例題の挙動差が出たら止める。
- 基準SHA、変更path、実行コマンド、total/pass/skip/fail、実行時刻を証拠に保存。
- 未実行をpassと書かない。ブラウザ未実施ならそのまま記載。
- MOD1は未完の親を維持。この分離だけでreleasedへ変更しない。
