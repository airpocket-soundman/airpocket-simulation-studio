# Operation correspondence (GUI / API / MCP / Skill)

[日本語](../operation-correspondence.md)

Companion to [API and MCP coverage](api-coverage.md). One row per browser operation (91) and per MCP tool (38: 36 default plus 2 when a browser origin is configured). `tests/operation-correspondence.test.mjs` compares the table with the operation and tool names in the source so it cannot silently drift.

- Scope/permission: browser operations use the scope in `src/browser-operation-names.js` (inspect/edit/analyze/view). MCP tools use the read-only/write annotation.
- GUI: each operation was classified by reading the page-building sources (`src/main.js`, `src/ui/*.js`, `src/*-ui.js`, `src/visual-export.js`) against the operation implementation (`src/browser-session.js`, the `*-operations.js` modules, and `scripts/studio-mcp.mjs` for MCP) and comparing the functions they call. `same path` means the GUI control calls the same shared function; `related, not the same operation` means it does something close but different (the reason is given); `connector only — no GUI control by design` means the code shows no GUI path (it does not claim a GUI could never be added). Per-row generated buttons have no id or class, so they are named by label and parent id. Limits: this is a static reading, not a check in a running browser; the classification compares shared functions and does not guarantee equal arguments, revision checks or permissions. `tests/operation-correspondence-gui.test.mjs` only verifies that every id, data attribute and class cited in the GUI column exists in the source; it does not verify the classification.
- Skill: files under `skills/airpocket-studio` that mention the name. "none" means no dedicated description.
- "saved-file counterpart" in the MCP column is a separate operation on saved JSON, not the same operation.
