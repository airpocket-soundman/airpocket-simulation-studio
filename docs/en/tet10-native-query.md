# Saved Tet10 dedicated point queries (2026-11-07)

`prepareNativeTet10Result(saved)` detaches a bounded plain own-data snapshot and validates versions, native metadata, input profile, runtime/input identity and `nativeResultRevision`. That canonical hash excludes the job envelope and revision itself, and excludes result.performance under the existing convention. It is content identity, not producer authentication, equilibrium, calibration or convergence certification.

Validation checks10-node connectivity, shared edge identity, exact converter midpoint coordinates, all nodes used, face incidence,6-node exterior faces, box bounds/volume and SAT interior-overlap refusal. Gauss locations, volumes, all stresses/von Mises and maxima are rederived from nodal displacements. Machine consistency tolerances are1e-4Pa+1e-8relative for stress,1e-10×max(1,largest box edge)mm for coordinates and1e-8mm³+1e-8relative for per-Gauss volumes. Midpoints must match the converter expression exactly. These are numerical tolerances, not engineering acceptance thresholds.

`sampleNativeTet10Result(handle, pointMm)` accepts only issued process-local handles. Actual quadratic shape functions and gradients evaluate displacement(mm), engineering strain `[xx,yy,zz,gammaXY,gammaYZ,gammaZX]`(dimensionless), and isotropic linear small-strain stress `[xx,yy,zz,xy,yz,zx]`(Pa). Millimetre displacement times1/mm gradient has the correct dimensionless strain; shear stress is μγ. No Gauss averaging or Tet4 downsampling occurs. Shared boundaries select the lowest containing element index, with barycentric tolerance64EPSκ capped at1e-8. Outside queries raise `TET10_NATIVE_OUTSIDE`; invalid records/handles raise `TET10_NATIVE_INVALID`. JSON-cloned handles are refused.

Limits are512 elements/4096 nodes, coordinates/displacements±1e6mm, E≤1e15Pa, ν≥−0.99 with the existing ν<0.49 restriction, and corner-Jacobian condition indicator≤1e6. Snapshot checks precede serialization: depth24,200000 values,65536-character strings,16384-element arrays,128-key objects and a conservative8MiB JSON-size estimate. Getters, holes, special prototypes and typed storage are refused. The existing one-box/whole-face fixed+total-force/no-gravity job profile remains.

Node `queryNativeTet10File({path, expectedRawSHA256, pointMm})` reads an8MiB cap+1 FD snapshot with no-links/regular-file and pre/post dev,ino,size,mtime,ctime checks. It refuses raw SHA mismatch, invalid UTF8/BOM, decoded duplicate keys and depth/value overflow, then returns one compact point. It creates no files, workers or solvers. Existing64MB job and2MB printed-reader limits remain unchanged. Files below8MiB can still exceed structural snapshot budgets.

[Evidence](../evidence/2026-11-07-tet10-native-query/report.json) retains one actual10mm cube job:24 Tet10/63 nodes and39044 saved bytes. Subsequent regressions only read that fixture. Independent affine/quadratic, rigid translation/infinitesimal rotation, ν=0.25 volumetric/shear formulas, rehashed tamper refusals, outside queries, ownership and concurrent-file edits are tested. Constructed polynomial records are interpolation oracles, not claimed load solutions. Finite-rotation objectivity, arbitrary CAD, common case/view/compare and parent P5B/98 completion remain outside this increment. Standard sampleResult native refusal remains.
