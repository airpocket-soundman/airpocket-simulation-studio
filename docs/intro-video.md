# 機能紹介動画（日本語版）の台本と制作手順

[English](en/intro-video.md)

## 未対応・未検証の注記

動画の字幕と終了カードに次を明記した。台本でも「乱流や圧縮性流れ、接触、GPU計算などは対応していない」と述べている。

- 乱流・圧縮性のCFD、接触解析、造形（プリント）解析、GPU計算、公開HTTPSサイトからの接続は未対応または未検証で、映像では扱っていない。
- 例題はすべて参照用のデモ（保存入力の根拠は未記録、`従来入力`）。疲労・破壊評価の材料データは架空で、寿命や破壊の保証ではない。
- MCPのシーンでは実際のLLM接続は行っていない。映しているのは接続パネル（未接続）、MCPサーバーのツール一覧、接続の概念図。
- モーダル／音響などの色分けは参照例題の表示であり、物理的な妥当性の検証結果ではない。

## 制作手順

作業フォルダは `C:\Users\<user>\Videos\airpocket-intro`（リポジトリ外）。主なファイルは次のとおり。

1. **環境**: 専用worktreeで`npm ci`、`node scripts/build-kernel.mjs`、`node scripts/copy-cad.mjs`を実行し、ビルド済みの`public/mfem`（WASM）は既存checkoutから読み取りコピーする（ネイティブの再ビルドは重いため）。`npx vite --host 127.0.0.1 --port 5190 --strictPort`で起動し、他の作業と衝突しないよう別ポートを使う。`ffmpeg`はwingetで導入済みのものを使用。Playwrightは`playwright-core`のみを作業フォルダへ入れ、実機のChromeを使う（ブラウザのダウンロードなし）。
2. **台本**: `narration.json`（シーンIDとナレーション）。
3. **素材撮り**: `scenes.mjs`（ソルバー系のシーン）、`ui_scenes.mjs`（疲労・破壊・ケース・接続パネル）。ページを開いてデモボタンをクリック→`#solve-run`→完了待ち→結果項目とアニメーション種別を設定→`#animation-preview`、をスクリプトで実行し、CDPスクリーンキャスト（JPEG 95）でフレームを保存。
4. **音声**: `tts.ps1`（`System.Speech`の`Microsoft Haruka`でシーンごとにWAVを生成）。
5. **合成**: `blib.py`（オーバーレイ・カード生成）、`build.py`（シーン定義→ffmpegでクロップ／拡大・字幕合成・シーンごとの音声配置）、`final.sh`（シーンの連結、BGM合成、`out/airpocket-intro-ja.mp4`の出力）。
6. **確認**: 全体を7.5秒間隔のフレームシートで目視、音量（最大−0.4 dB）を確認。

## 作れた範囲と作れなかった範囲

- 作れた: 構造（線形弾性・弾塑性・超弾性）、熱、音響（調和・過渡・外部放射）、モーダル、流体（流路・Stokes）、疲労・脆性破壊評価、ケース比較、MCP／API接続（パネルとツール一覧）を含む約3分の日本語ナレーション付きMP4。
- 作れなかった・簡略化した点: PNG／WebM出力の実演、実際のLLMからの操作の実演、Stokes流の速度場の映像（表面表示では箱の外面が単色で内部が見えなかったため、解析メッシュ表示で代替）、`THERMAL STRESS`・内部流路・疲労評価以外の評価機能、英語版（後日）。BGMとナレーションの聴感確認は音量の機械測定のみで、人の耳での最終確認は未実施。
