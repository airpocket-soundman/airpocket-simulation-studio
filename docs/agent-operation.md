# LLMを主な操作主体とするAPIとMCPの仕様

[English](en/agent-operation.md)

策定日: 2026-10-14。目標は、利用者のLLMエージェントが全機能を操作し、実行途中の情報から条件や次の解析を調整できるCAE基盤とすること。GUIとエージェントは共通機能を利用する。この文書は目標仕様であり、現在の対応範囲とは区別する。

## 最優先の製品原則（2026-10-14確定）

最大の差別化要因は、ユーザー自身のLLMが専門SKILLを通じて本アプリの全機能を自由に組み合わせ、解析と設計反復を進められることである。独自AIを設計・提供してAIサブスクリプションへ誘導する構成を製品の前提にしない。LLMの選択・契約・実行環境はユーザー側にあり、本アプリは共通API、MCP、専門SKILL、検査と結果の証跡を提供する。

最優先事項は、全利用者機能のAPI化とMCP対応、専門SKILLの継続育成、中間結果をLLMへ返すパイプラインの整備である。準備・メッシュ品質・反復/残差・時間ステップ・暫定測定値をジョブIDと入力版に結び付け、要約と詳細成果物参照を取得できるようにする。中間の場を提供できないソルバーは制限を明示する。LLMが観測して次の設定を準備できても、実行中スナップショットを変更しない。

GUI機能を追加する際は、意味的API・MCP・状態/診断・SKILLでの使い方と検証例を同じ作業として扱う。SKILLは現行能力、単位、物理的前提、失敗からの修復、暫定/最終結果の区別を教え、モデルやソルバーを黙って変更しない。API網羅率、MCPだけでのタスク完了率、中間情報の観測と再設定、SKILLによる例題の再現性を受け入れ指標とする。

## 対応レベル

| レベル | 到達条件 |
|---|---|
| 1 操作可能 | 一部の設定・解析をAPIから呼べる |
| 2 一連の解析 | 形状取り込み、領域、材料、条件、メッシュ、実行、結果取得ができる |
| 3 状態と診断 | 対応能力、現在状態、不足情報、単位付き診断、修正候補を取得できる |
| 4 反復運用 | 中間情報、ジョブ管理、差分変更、検査、再実行と比較ができる |
| 5 全機能と設計反復 | ビューア・出力・保存を含む全利用者機能をMCPから操作し、根拠と設計版を追跡してCADとの反復を進められる |

Airpocketはレベル5を目標とする。ツール数の多さでは評価せず、実際の操作経路の網羅率、状態の観測、修復、再現性と反復の負担で評価する。競合のレベルは同じシナリオで検証してから判定し、公開APIの有無だけで高低を決めない。

## 全機能を共通操作へ

形状取り込み・領域選択・材料・条件・設定・メッシュ・実行・比較・点測定・時間操作・カメラ・レイヤー・アニメーション出力・保存・復元を共通操作として定義し、MCPから呼べるようにする。マウスジェスチャーは領域やカメラの意味的操作へ変換する。エージェントに画面座標クリックを必須にしない。

GUI機能と共通操作とMCPの対応表を管理する。新規の利用者機能は対応操作・検査・診断・状態取得を同時に設計する。ブラウザのファイル選択等を使わずに操作できる代替経路を用意する。通信や保存先の権限はAPI操作と別に検査する。

## 中間結果とジョブ

| 段階 | エージェントに返す情報 |
|---|---|
| 準備 | モジュール取得・初期化の進捗、キャッシュ、必要資源 |
| メッシュ | 要素数、品質、不良領域、境界転送誤差、細分化履歴 |
| 計算 | 反復数、残差、収束傾向、経過時間、利用可能な資源指標 |
| 時間解析 | 完了した時間ステップ、暫定の測定値・場、時間積分状態 |
| 評価 | 収支、メッシュ依存性、適用範囲、比較候補 |

中間の場はソルバーが有効なスナップショットを返せる場合に取得する。未収束値を最終結果として扱わず、入力版、ジョブID、時刻/反復、収束状態、暫定表示を付ける。情報を返せないソルバーでは対応能力に制限を示す。

開始はジョブIDをすぐ返し、イベント通知または版付き状態取得で観測する。新しいイベントだけを取得でき、更新頻度とペイロードを制限する。大きな場は成果物参照で返し、LLMには要約・測定・領域統計を優先する。切断後も状態を確認でき、同じ要求の再送でジョブや出力が重複しない契約を設ける。

## 素早い条件再調整

エージェントは現在状態を確認し、差分設定案を検査して一括適用し、必要な部分だけ再計算する。変更は原子的に扱い、期待する入力版を指定して古い状態への上書きを拒否する。誤った変更を戻せる履歴を保持する。

形状、領域、メッシュ、材料、境界条件、剛性・前処理等の依存関係を追跡する。入力と版が一致し再利用が数学的に妥当な場合だけキャッシュを使う。例えば線形解析の荷重変更でも拘束・材料・メッシュが変われば同じ再利用条件とは限らない。非線形解析の履歴や初期状態は独立した入力として扱う。

実行中の入力スナップショットを変更しない。変更案は次の実行用に準備し、必要なら現在ジョブを中止して新規実行する。途中変更や再開は明示的に対応したソルバーだけに許可する。再利用できる部分と無効化される部分を準備段階で返す。

## LLMが扱いやすい契約

- 型、単位、有効範囲、列挙値、必要入力を機械可読にする。
- 現在実行可能な操作と、できない理由を取得できるようにする。
- 小さな目的別操作と、一連の処理をまとめる操作の両方を提供する。
- 安定した部品・領域・結果IDを使い、意味的な選択と名前付き領域を提供する。
- 既定値の理由、仮定、出所、未確認事項を保存し、診断に修復候補を含める。
- 要約取得と詳細取得を分け、ツール説明と対応能力を必要に応じて取得できるようにする。
- 数値データ、ビュー設定、画像・動画を同じ結果版へ関連付ける。

## 検証と比較の指標

初心者のブラケット例題で、確認質問から形状・設定・解析・修復・再解析・比較・動画出力までをMCPだけで完了できることを検証する。GUIとの状態整合、実行中変更、中止、切断、重複要求、古い版、不正入力を確認する。

指標は機能網羅率、タスク完了率、利用者の手作業、呼び出し数、返却データ量、診断からの修復成功率、初回と反復の時間、キャッシュ再利用率、結果の再現性とする。LLM運用のしやすさはこれらを同条件で比較して評価する。

現行の不足は[API・MCP対応表](api-coverage.md)で追跡する。
